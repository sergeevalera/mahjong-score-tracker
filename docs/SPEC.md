# Спецификация: Счётчик очков для Ма-Джонга

## 1. Общее описание

**Название:** Маджонг-счётчик  
**Тип:** Веб-приложение (React PWA)  
**Языки интерфейса:** Русский, English (с возможностью добавления новых языков)  
**Платформы:** Браузер, Android, iOS (через «Добавить на главный экран»)  
**Целевая аудитория:** Ведущий за столом японского маджонга, который вводит данные за всех игроков

---

## 2. Правила игры (релевантные для подсчёта)

### 2.1. Структура партии

- Партия состоит из **4 раундов** (ветров): Восточный → Южный → Западный → Северный.
- Каждый раунд состоит из **4 раздач**.
- Итого в полной партии — **16 раздач**.
- **Преимущественный ветер (Восток)** — определяется для каждой раздачи.

### 2.2. Назначение Востока

- **Первая раздача:** ведущий вручную назначает, кто является Востоком.
- **Последующие раздачи:** если Восток собрал Ма-Джонг — он остаётся Востоком. Если победил другой игрок или ничья — Восток переходит к следующему игроку (по часовой стрелке: Восток → Юг → Запад → Север).

### 2.3. Ничья (несыгранная раздача)

- Очки не считаются и не переносятся.
- Восток **не сдвигается**.
- Счётчик раундов **прокручивается** (раздача считается сыгранной).

### 2.4. Правила взаиморасчёта

#### Шаг 1 — Платежи победителю

Каждый из трёх проигравших платит победителю **полную стоимость** его комбинации.

#### Шаг 2 — Расчёт между проигравшими

Проигравшие рассчитываются попарно: тот, чья комбинация дешевле, платит **разницу** в стоимости тому, чья дороже.

#### Шаг 3 — Множитель Востока (×2)

Если **Восток победил** — все проигравшие платят ему **двойную** стоимость его комбинации (вместо обычной).

Если **Восток проиграл** — он платит победителю **двойную** стоимость комбинации победителя (вместо обычной). В расчётах между проигравшими Восток также получает или выплачивает **двойную** сумму.

## 3. Функциональные требования

### 3.1. Экран настройки партии

- Ввод имён 4 игроков.
- Выбор начального Востока (кто из четырёх).
- Кнопка «Начать партию».

### 3.2. Главный экран (раздача)

#### Отображение состояния

- Текущий раунд (ветер): Восточный / Южный / Западный / Северный.
- Номер раздачи внутри раунда: 1 / 2 / 3 / 4.
- Общий номер раздачи: 1–16.
- Кто сейчас Восток (выделен визуально).
- Текущие балансы всех 4 игроков.

#### Ввод результата раздачи

- **4 поля ввода** — по одному для каждого игрока (стоимость комбинации, число).
- **Отметка победителя** — кнопка/переключатель «Ма-Джонг» рядом с именем игрока (можно выбрать только одного).
- **Кнопка «Ничья»** — для несыгранной раздачи.
- **Кнопка «Рассчитать»** — выполняет взаиморасчёт и переводит к следующей раздаче.

#### Отображение результата

После расчёта показать:
- Кто кому сколько заплатил (все 6 пар).
- Как изменился баланс каждого игрока.
- Новые балансы.

### 3.3. История раздач

- Список всех сыгранных раздач.
- Для каждой раздачи: номер, кто был Востоком, кто победил (или ничья), введённые очки, результат расчёта.
- **Кнопка «Отменить последнюю раздачу»** — откатывает балансы и возвращает к предыдущему состоянию.

### 3.4. Итоговый экран

- Финальные балансы всех игроков.
- Общий итог: кто кому сколько должен (сводка по всей партии).
- Возможность начать новую партию.

## 4. Логика расчёта (алгоритм)

### Входные данные раздачи

```
players[0..3] = { name, score }   // введённые очки комбинации
winnerIndex                        // кто собрал Ма-Джонг (0–3 или null для ничьей)
eastIndex                          // кто сейчас Восток (0–3)
```

### Алгоритм (не ничья)

```
1. Инициализировать transfers[i][j] = 0 для всех пар

2. Для каждого проигравшего L (L ≠ winner):
   payment = players[winner].score
   if (L === eastIndex || winnerIndex === eastIndex):
       payment *= 2
   transfers[L][winner] += payment

3. Для каждой пары проигравших (L1, L2), где L1 ≠ winner и L2 ≠ winner:
   diff = |players[L1].score - players[L2].score|
   cheaper = тот, у кого score меньше
   expensive = тот, у кого score больше
   payment = diff
   if (cheaper === eastIndex || expensive === eastIndex):
       payment *= 2
   transfers[cheaper][expensive] += payment

4. Обновить балансы:
   Для каждой пары (i, j):
       net = transfers[i][j] - transfers[j][i]
       balances[i] -= net
       balances[j] += net
```

### Алгоритм (ничья)

```
Ничего не менять в балансах.
Восток не сдвигается.
Раздача считается сыгранной — перейти к следующей.
```

### Переход Востока после раздачи

```
if (ничья):
    eastIndex не меняется
else if (winnerIndex === eastIndex):
    eastIndex не меняется
else:
    eastIndex = (eastIndex + 1) % 4
```

## 5. Структура данных (состояние приложения)

```typescript
interface Player {
  name: string;
  balance: number;   // текущий баланс (начинает с 0)
}

interface Round {
  roundNumber: number;        // 1–16
  windRound: "east" | "south" | "west" | "north";  // ключ ветра (для i18n)
  windRoundNumber: number;    // 1–4 (номер раздачи внутри ветра)
  eastIndex: number;          // кто был Востоком (0–3)
  isDraw: boolean;            // ничья
  winnerIndex: number | null; // кто победил
  scores: number[];           // введённые очки [4 числа]
  transfers: Transfer[];      // список переводов
  balanceChanges: number[];   // изменения баланса [4 числа]
}

interface Transfer {
  from: number;    // индекс плательщика
  to: number;      // индекс получателя
  amount: number;  // сумма
}

interface GameState {
  players: Player[];
  rounds: Round[];
  currentRound: number;      // 1–16
  currentEastIndex: number;  // 0–3
  isFinished: boolean;
  locale: string;            // "ru" | "en" | ... (выбранный язык)
}
```

## 6. Экраны и навигация

```
[Настройка партии] → [Главный экран] → [Итоговый экран]
                          ↕
                    [История раздач]
```

### Экраны

1. **Настройка партии** — имена игроков, выбор Востока.
2. **Главный экран** — ввод результата текущей раздачи, балансы.
3. **История раздач** — список прошлых раздач, кнопка отмены.
4. **Итоговый экран** — финальные балансы, сводка долгов, новая партия.

## 7. Технический стек

- **React** (функциональные компоненты, хуки).
- **TypeScript** (строгая типизация).
- **CSS** — встроенные стили или CSS-модули (без внешних UI-библиотек для прототипа).
- **PWA** — manifest.json + service worker для установки на телефон.
- **i18n** — `react-i18next` + `i18next` для мультиязычности. Переводы хранятся в JSON-файлах (`locales/ru.json`, `locales/en.json`). Язык по умолчанию определяется по настройкам браузера, с возможностью переключения вручную.
- **Хранение данных** — localStorage (состояние партии и выбранный язык сохраняются между сессиями).

---

## 7.1. Интернационализация (i18n)

### Принципы

- Все строки интерфейса вынесены в файлы переводов — в коде компонентов нет хардкод-текста.
- Язык по умолчанию: определяется через `navigator.language` (русский для `ru*`, английский для остальных).
- Пользователь может переключить язык в настройках приложения (доступно с любого экрана).
- Выбранный язык сохраняется в localStorage.

### Структура файлов переводов

```
src/
  locales/
    ru.json
    en.json
```

### Добавление нового языка

Для добавления нового языка достаточно:
1. Создать файл `src/locales/{код_языка}.json` по образцу существующих.
2. Зарегистрировать его в конфигурации i18next.
3. Добавить опцию в переключатель языка.

### Что переводится

- Названия экранов и кнопок.
- Названия ветров (Восточный / East, Южный / South и т.д.).
- Системные сообщения (ничья, победитель, ошибки ввода).
- Подписи к полям ввода и таблицам.

### Что НЕ переводится

- Имена игроков (вводятся пользователем).
- Числовые значения очков.

## 8. Ограничения прототипа

- Без правила «Дом полон» (лимит очков).
- Без автоматического подсчёта хан/фу — пользователь вводит готовую стоимость комбинации.
- Без сезонов и цветов.
- Без системы пенальти (штрафов).
- Без лимитированных комбинаций.
- Без серверной части — всё работает локально в браузере.

## 9. Пример сценария

### Раздача 1

- Игроки: Алиса, Боб, Вика, Глеб.
- Восток: Алиса.
- Победитель: Боб (30 очков).
- Очки остальных: Алиса — 22, Вика — 10, Глеб — 4.

**Расчёт:**

Платежи победителю (Бобу):
- Алиса → Боб: 30 × 2 = **60** (Алиса — Восток, платит двойную)
- Вика → Боб: 30
- Глеб → Боб: 30

Расчёт между проигравшими:
- Вика (10) vs Глеб (4): Глеб → Вика = 6
- Алиса (22) vs Вика (10): Вика → Алиса = 12 × 2 = **24** (Алиса — Восток)
- Алиса (22) vs Глеб (4): Глеб → Алиса = 18 × 2 = **36** (Алиса — Восток)

Изменения балансов:
- Алиса: −60 + 24 + 36 = **0**
- Боб: +60 + 30 + 30 = **+120**
- Вика: −30 + 6 − 24 = **−48**
- Глеб: −30 − 6 − 36 = **−72**

Восток: Алиса не победила → Восток переходит к Бобу.
